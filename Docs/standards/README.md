# Standards — TACE.Oracle.Admin

The rules this repo is held to. They apply the same way to code written by a
person and code generated by an AI.

| File | Covers |
|---|---|
| [coding.md](coding.md) | PowerShell coding rules, output contract, error model, logging |
| [security.md](security.md) | Credential handling, scrubbing, process isolation, STIG controls |
| [testing.md](testing.md) | Pester structure and what every test file must contain |
| [documentation.md](documentation.md) | Required project documents and how they are kept current |
| [invariants.md](invariants.md) | The format of the invariant block every function carries |
| [invariants-index.md](invariants-index.md) | Generated: every invariant, one line each, and what enforces it |
| [decisions.md](decisions.md) | Rules that were contested, what was decided, and what is deferred |

Commit and release rules are in [VERSIONING.md](../VERSIONING.md).

## How to read a rule

Each rule is one sentence and one example, with an ID and the layer that enforces it.

| Enforced by | Meaning | Built in |
|---|---|---|
| Linter | A machine check gives the same answer every time | Stack 2 |
| Test | A Pester test proves it | Stack 3 |
| Review | It needs judgement; a reviewer checks it | Stack 6 |

A rule that cannot be written as one sentence and one example is too vague to be a
rule, and is recorded in `decisions.md` until it can be.

## Invariants

A standard applies to every function. An invariant applies to one function: what it
must do and must never do.

Invariants are recorded in the code, in an `# INVARIANTS` comment block at the top of
each function body, not in a separate document. They travel with the function, appear
in the same diff as a change to it, and are read by whoever, or whatever, edits it next.

The block format is defined in [invariants.md](invariants.md). The index is generated
from the blocks by `Tests\Lint\Invoke-InvariantLint.ps1`. It is also the invariant-to-test
map: each invariant is listed with the tests or static checks that prove it. A test in
`Tests\Static\` fails when a function has no block, an entry is malformed or names no
proof, a cited test does not exist, or the committed index is out of date.

## Agent instructions

`AGENTS.md` at the repository root is generated from `coding.md`, `security.md`,
`testing.md`, `documentation.md` and `invariants.md` by
`Scripts\Export-AgentInstruction.ps1`, and is never edited by hand. Cursor reads it
directly. Claude Code reads it through a local, gitignored `.claude\CLAUDE.md` that
holds `@../AGENTS.md`. A test in `Tests\Static\` fails when the committed `AGENTS.md`
does not match these files.
